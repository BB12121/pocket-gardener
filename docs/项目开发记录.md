# 口袋园丁项目开发记录

## 1. 项目概况

口袋园丁是一个面向家庭植物养护场景的全栈应用。项目围绕植物档案、养护任务、养护日志、天气提醒、AI 养护建议、植物识图、社区互动和个人成就等功能展开，目标是帮助用户以较低成本记录植物状态、安排养护计划，并通过社区获得经验支持。

项目采用前后端分离结构。前端使用 React 和 Vite 构建移动端优先的 Web 应用，并通过 Capacitor 补充 Android 调试包能力；后端使用 Spring Boot 提供 REST API，使用 JPA 管理业务数据，使用 Flyway 管理数据库结构演进。开发过程中遵循“需求分析、模块设计、编码实现、测试验证、版本管理”的基本软件工程流程。

### 2026-05-31：点赞与关注逻辑修复

本阶段根据测试体验修复社区模块中不符合正常社交产品逻辑的问题。

发现的问题：

- 点赞按钮可以重复点击并持续增加数量。
- 帖子缺少“当前用户是否已点赞”的状态。
- 关注状态原先更接近全局状态，不够符合多用户系统逻辑。
- 帖子列表中“已关注”状态不能直接取消关注。

处理方式：

- 后端新增帖子点赞关系表，使用“帖子 + 用户”的唯一关系记录点赞状态。
- 后端新增社区关注关系表，使用“关注者 + 被关注者”的唯一关系记录关注状态。
- 点赞接口改为切换行为：未点赞时点赞，已点赞时取消点赞。
- 关注接口改为当前用户维度的切换行为。
- 聚合数据接口返回当前用户对帖子的点赞状态。
- 前端点赞按钮增加已点赞样式、点击动效和防重复提交处理。
- 前端关注按钮支持“关注 / 已关注”之间切换。
- 增加后端回归测试，覆盖点赞切换和关注状态隔离。

## 6. 关键问题与处理记录

| 问题 | 原因 | 处理结果 |
|---|---|---|
| 登录后页面无法进入 | 前端运行环境请求地址指向旧后端端口 | 重启前端并显式指定 API 地址为当前后端地址 |
| 数据库迁移后旧 jar 无法覆盖 | 旧后端进程占用 jar 文件 | 停止旧进程后重新打包并启动新版后端 |
| 社区点赞数量异常增长 | 缺少用户维度的点赞关系记录 | 新增点赞关系表并实现切换点赞 |
| 关注状态不符合多用户逻辑 | 关注记录未按当前用户隔离 | 新增关注关系表并按当前用户返回关注列表 |
| Android 构建依赖前端最新产物 | 修改前端后需要同步到 Android 工程 | 使用 `npm run android:sync` 后再执行 Gradle 构建 |
